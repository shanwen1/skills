# 为了省 Token，我做了一个让 GPT 和 Codex 自主对话的 Skill

> **GPT-Codex Bridge** · Stop copy-pasting. Let agents review each other's work.

先说说我为什么会做这个东西。

我就是个普通的 ChatGPT Plus 用户。之前用 Sol 跑复杂任务，经常半小时左右 Token 就见底。可我又不想因为额度不够，就只能让一个模型从头干到尾——理解需求、写代码、改小问题、跑测试、再改，再测，所有事情都让高成本模型做，实在有点浪费。

我就想：**GPT 不是能帮我做高级判断吗？那我把它当审查大脑，执行的活交给 DeepSeek Flash 这类成本更低的模型，不就好了？**

GPT 负责把需求想清楚、定验收标准、检查真实成果；执行模型负责改文件、跑测试、修问题。GPT 说没过，就按意见接着修；等整个目标真的通过验收，再停下来。

道理听起来简单，实际操作却很烦：

> ChatGPT 里聊清楚需求 → 复制给 Codex → 等它干活 → 把结果复制回来 → GPT 说这里不对 → 我再复制给 Codex……

**我不是在开发，我是在给两个 AI 当传话筒。**

所以我做了 `gpt-codex-bridge`。它利用已有的、经过授权的浏览器操作能力，让执行 Agent 自动把结果发回原来的 ChatGPT 对话；GPT 再通过 GitHub 独立核对真实提交、Diff、源码和测试。不通过就继续修，Push 新 SHA，再让 GPT 看一遍。

**我想要的体验是：目标讲清楚一次，剩下的让它们自己跑。等我忙完回来，看到的是进展和证据，而不是一堆等着我转发的消息。**

## 它到底帮我省了什么？

不只是省复制粘贴，还想把“执行”和“验收”分开。

```text
我把目标讲清楚
      │
      ▼
Codex / 执行模型读实际文件、修改、自测
      │
      ▼
提交并 Push 到 GitHub
      │
      ▼
GPT 回到原来的 ChatGPT 对话，独立检查最新 SHA
      │
      ├─ FIX：只指出当前最重要的差距，交回去修
      ├─ UNVERIFIED：证据不足，先补证据
      └─ PASS：全部验收项满足，整个目标才算完成
                    │
                    └── 修复 → 新提交 → 再审
```

这里我特别在意一件事：**执行模型不能自己说“搞定了”，就算真的搞定了。** 对代码任务，GPT 要自己读取 GitHub 上的实际提交和相关文件，并确认审查的 SHA 就是当前版本。否则，审查的可能是旧代码，或者只是执行模型写得很漂亮的一份总结。

## 我踩过的坑：Luna 不一定适合这类长循环

一开始我以为，只要 Skill 里写清楚“目标没完成就继续”，所有执行模型都会照着做。结果不是这样。

在我目前的配置里，Luna 好几次在整体目标还没完成时，就提前总结并停止了。反过来，我只跟 DeepSeek Flash 交代了一次要做桥接的事，下午忙起来把这件事忘了，它还在持续干活。

所以我现在的经验是：**选执行模型，不能只看它单轮回答聪不聪明，还得看它能不能连续跑完交接、审查、修复、复验。**

在这项任务上，我暂时不再用当前配置的 Luna，优先用已经实测能持续推进的 DeepSeek Flash。这是我自己的实测经验，不代表 Luna 的所有版本和配置都不行。真正要做长任务前，先拿一个低风险任务跑一遍完整闭环；如果它总在半路收工，先换模型验证，别一味给 Skill 加长提示词。

## 它能做什么？

我目前最想用它做的是那些“方向已经说清楚，但细节需要反复打磨”的工作：

- **写代码、修 Bug**：执行模型修完以后，GPT 直接看新提交，不用我手动搬运报错和 Diff。
- **前端 UI 和用户旅程**：GPT 按最初的目标检查页面和代码，没达标就交回去继续改。
- **复杂重构、补测试**：每轮都对着新的 SHA 复核，不因为某个测试过了就宣布整体完成。
- **PR 前审查**：让另一个模型独立核验实际代码，但不会因为 PASS 就自动合并。
- **文档、研究等共享产物**：只要双方都能访问同一份真实成果，也能用类似方式交接和复核。

简单说，它适合那些**有明确目标和验收标准、需要反复迭代，而我又不想一直盯着每一轮执行**的任务。

## 为什么还要看 GitHub？

因为“我改完了”和“需求真的实现了”是两回事。

代码任务里，我希望每次交接都带上 `run_id`、`turn_id`、基线 SHA 和最新 SHA。GPT 自己读取远端提交、Diff、相关源码和测试，再给出 `PASS / FIX / UNVERIFIED`。

- SHA 对不上，就不接受这轮审查结果。
- GPT 返回 `FIX`，执行模型就只处理当前最重要的差距，重新测试并 Push 新 SHA。
- GPT 返回 `UNVERIFIED`，能在现有权限内补证就先补证。
- 只有 GPT 确认**整个目标的全部验收项**都满足，才算完成。

这套做法不是为了让流程显得复杂，而是防止两个 AI 互相说“你做得不错”，最后真正的代码却没人看。

## 怎么用？

### 第一步：安装

```bash
git clone https://github.com/shanwen1/skills.git
mkdir -p ~/.agents/skills
cp -R skills/gpt-codex-bridge ~/.agents/skills/
```

在 Codex 中调用 `$gpt-codex-bridge`。如果当前客户端没刷新出 Skill，可以重新打开会话再试。

### 第二步：准备原来的 ChatGPT 对话

先在 ChatGPT 里把目标和验收条件讲清楚，然后复制**这条现有对话的完整 URL**。不要让执行 Agent 自作主张新开一个会话，否则前面讨论的目标和约束可能就丢了。

执行端还必须有经过授权、确实能访问已登录 ChatGPT 页面的浏览器工具；GPT 审查端要能访问对应的 GitHub 仓库或共享产物。**安装 Skill 本身不会自动获得浏览器权限。**

### 第三步：告诉执行 Agent

把下面这段交给 Codex 或你实际使用的执行 Agent，把 URL 换成当前对话地址：

```text
使用 $gpt-codex-bridge。

沿用这条 ChatGPT 对话中已经明确的目标和验收要求：
<完整 ChatGPT 对话 URL>

使用已授权的浏览器能力与该对话自动交接。
完成任务并自测；仅在已授权范围内提交到独立 Git 分支。
让 GPT 独立核验整个目标的全部验收项。
FIX 就修复并再次送审；UNVERIFIED 就先补证。
只有最新成果通过整体验收才标记 DONE；否则在当前会话内继续。
遇到权限、预算或不可恢复故障时保存检查点并说明原因。
不要合并 main、发布、部署或修改生产数据。
```

第一次连接时，先确认 `BRIDGE_PING / BRIDGE_PONG` 确实成功。能打开网页不等于已经打通消息收发。

更详细的配置放在 [GPT 端审查指令](CHATGPT_INSTRUCTIONS.md)、[交接协议](references/protocol.md)、[浏览器传输说明](references/transport.md) 和 [中断恢复规则](references/recovery.md)。

## 那我能不能交代完就去睡觉？

这正是我想要的效果：**少盯着它干活，第二天起来看进展。** 但我也不想把一个 Skill 吹成永动机，所以边界还是要讲清楚。

- Skill 会要求执行 Agent 在当前运行会话里持续推进，不能只修完一小处就把整体目标当作完成。
- 如果模型额度耗尽、平台结束当前执行轮次、浏览器断开或电脑休眠，Skill 本身不能凭空唤醒 Agent。真正的通宵无人值守，需要环境里有已启用、已授权且经过验证的持续运行或恢复机制。
- “省 Token”是我做这个东西的原因，不是经过基准测试的节省比例。它主要减少重复解释和手动搬运；GPT 独立审查也会消耗 Token。
- 不默认合并、发布、部署或操作生产数据。证据不足、权限不够或连续没有进展时，应该保存状态并说明原因，而不是装作任务已经完成。

**我想省的不是思考，而是反复传话和守着每一轮执行的时间。** 把判断交给 GPT，把重复执行交给更适合的模型，把真实证据留在 GitHub——这就是我做这个 Skill 的出发点。

如果你也每天在 ChatGPT 和 Codex 之间来回复制，希望它能帮你少做一点“人肉桥接”。
