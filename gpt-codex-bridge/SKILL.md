# GPT ↔ Codex Bridge

目标：跨平台转交**目标、依据、边界和结果**，避免反复解释、上下文丢失与“汇报即验收”。这是通用协作协议，不是某个项目的开发流程，也不是跨平台自动通信程序。

## 核心原则

1. **按能力分工，不按模型强行分工。** GPT 侧通常理解目标、做判断、设计验收和审阅结果；Codex 侧通常读取可访问的工作区、执行操作、验证结果。两端都可提出纠错意见；用户拥有最终授权权。
2. **任何一端只能声称已亲自核查过的内容。** 聊天记录、路径、链接和他方回报只是线索；需要时应重新读取当前文件、页面、代码或数据。不能访问就标记“未核验”。
3. **交接以最小充分上下文为单位。** 不复制整段历史；写清目标、影响结果的已定决策、必需输入的位置或摘录、边界、验收、待确认事项。
4. **不要求所有任务走 Git 或浏览器。** 代码任务核对代码/版本和测试；文档任务核对实际文稿；研究任务核对来源及推断；数据任务核对输入、计算和输出。证据形式由任务决定。
5. **不擅自扩权。** 本 Skill 不授权发送消息、修改外部系统、提交/推送、合并、发布或不可逆操作。沿用用户明确授权和实际环境权限；敏感凭据不写入交接包。
6. **完成即停止。** 一轮围绕一个清晰、可验收的结果；如确需多步完成，可由执行者自行拆分，但不顺势增加目标。

## 入口 A｜GPT → Codex：发任务

只在用户希望 Codex 参与时生成 `BRIDGE_TASK`；不是必须由 GPT 先设计完整实施步骤。

```text
【BRIDGE_TASK】
目标：<本轮要达到的结果，含业务目的>
已知上下文：<仅影响执行的既定事实/决定；区分事实与假设>
输入与位置：<附件、文件、路径、仓库、链接、文本摘录；写明哪些端可访问>
边界与授权：<哪些必须保持不变；能做/不得做的操作>
验收：<用户怎样判断结果可用，含必要证据>
交付：<结果形式及 BRIDGE_HANDOFF>
```

如果对方无法访问 GPT 对话/附件，必须把关键资料直接放入任务包或明确提供可访问的位置。禁止使用“按我们昨晚说的”替代实际必要上下文。

## 入口 B｜Codex → GPT：交结果

Codex 先完成能完成的工作并自行检查，再交接。交接必须**可独立理解且可复核**，对无修改任务不虚构提交记录。

```text
【BRIDGE_HANDOFF】
目标与状态：<完成 / 部分完成 / 阻断>
实际产出：<做了什么，产物路径/链接/关键摘录>
已验证：<验证方法、结果、证据位置；如有版本写清标识>
未验证或风险：<仍不能确定的事及其影响；无则写无>
需决策：<仅需要用户/GPT 决定的事项；无则写无>
```

按任务类型附加关键证据：代码可包含仓库、分支、SHA、Diff 与测试；文档包含具体文件及检查点；研究包含来源链接、日期与事实/推断分界；数据包含输入版本、处理口径与校验结果。仅提供当前任务所需的最少信息。

## 入口 C｜GPT 审阅回执：核验或继续

先确认是否真正能读到产物和关键证据；**“Codex 说完成了”不等于已核验**。不得为了继续循环而强行制造新任务。

```text
【BRIDGE_REVIEW】
结论：PASS / FIX / UNVERIFIED
依据：<GPT 实际检查到的成果或证据；他方自述明确标注>
差距：<影响验收的核心问题；没有则写无>
下一步：DONE / <一条最小必要的 BRIDGE_TASK>
```

- `PASS`：符合目标且必要证据充分，回 `DONE`。
- `FIX`：存在明确偏差，只下发一条具体修正任务。
- `UNVERIFIED`：关键证据不可访问或未运行，不伪称通过；索取或执行最小验证，不要求重做已完成工作。
- 只有目标/权限冲突、不可逆操作或会实质影响结果的不确定性，才让用户决策。

## 跨平台通信与状态

- 默认由用户**复制粘贴** `BRIDGE_TASK` 与 `BRIDGE_HANDOFF`；只有存在真实可用且已获授权的工具时才可自动传递。
- GPT 不默认读取 Codex 本地文件或工作目录；Codex 不默认读取 ChatGPT 的聊天历史、记忆和附件。路径不是内容，文件已生成也不代表另一端可访问。
- 新会话、长任务或中途换 Agent：先给一份新的最短 `BRIDGE_HANDOFF` 或 `BRIDGE_TASK`，说明当前状态与证据入口，禁止将旧的计划伪装成当前进度。
- 有项目级规范时优先遵循，如现有 `AGENTS.md`、文档模板、项目验收契约；不把单个项目的产品规则带到其他项目。
